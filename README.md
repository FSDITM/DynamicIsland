# DynamicIsland

Динамический островок для Windows. Переработанная версия
[DynamicWin](https://github.com/FlorianButz/DynamicWin) Флориана Бутца
с новым ядром отрисовки.

## Почему не форк «как есть»

Исходники DynamicWin удалены из репозитория 19 октября 2025 года (коммит
`Remove initial version`, −10 245 строк); там теперь только релизы. Код
восстановлен из истории git и лежит рядом в `../upstream-src` как справочник.

Главная проблема оригинала была не в мелочах, а в архитектуре ядра:

| Что было | Что стало |
|---|---|
| Полноэкранное прозрачное WPF-окно (`AllowsTransparency`) — layered window, весь экран через CPU каждый кадр | Окно-«сцена» размером с островок, `WS_EX_NOREDIRECTIONBITMAP` + DirectComposition, кадр не покидает GPU |
| Софтверный Skia (`SKSurface.Create` поверх `WriteableBitmap`) | Skia на Direct3D 12 через `SkiaSharp.Direct3D.Vortice` |
| 60 fps всегда, даже в покое | Кадр только когда есть что менять; в покое поток спит на нуле CPU |
| WMI-запрос яркости каждый кадр в UI-потоке | Системные метрики — фоновым опросом с кэшем |
| `Vec2` — class, `new List<>` в `Update`/`Draw` каждого объекта каждый кадр | `Vec2` — readonly struct, отрисовка без аллокаций |
| `new SKPaint` / `SKImageFilter` каждый кадр без `Dispose` | Кисти и фильтры кэшируются |

## Замеры

`--selftest` гоняет анимацию и пишет метрики в `dynamicisland.log`.
На AMD Radeon (Ryzen 5 6600H), сцена 1000×300 @ DPI 144:

```
анимация:  60.0 fps, CPU 7.1% одного ядра, 1.18 ms CPU на кадр
первый кадр 70 ms (компиляция шейдеров, разово)
простой:   0.000% одного ядра за 20 с — поток спит полностью
память:    86 МБ приватной, 134 МБ рабочий набор
```

Стоимость кадра считается как отрисовка + flush + present. Ожидание fence —
это сон в ожидании GPU, а не работа процессора, и в стоимость не входит.

## Возможности

- Часы и заряд батареи в компактном виде; когда играет музыка — живой эквалайзер
  (~18 кадров в секунду, только пока музыка действительно играет)
- При наведении раскрывается в плеер: обложка, название, исполнитель,
  пауза, переключение треков и **полоса перемотки** — тянется мышью,
  время с обеих сторон; через штатный Windows-API
  `GlobalSystemMediaTransportControls` (работает со Spotify, браузерами,
  любыми плеерами без плагинов)
- **Показ нового трека:** при смене песни островок сам раскрывается на
  несколько секунд и сворачивается обратно
- Кнопки плеера подсвечиваются под курсором
- Все иконки — вектор, без зависимости от глифов шрифта
- **Умная адаптация формы:** под развёрнутым окном сворачивается в тонкую
  полоску у края экрана, в полноэкранном режиме (игра, видео) убирается совсем
- Мышь проходит сквозь оверлей везде, кроме самой фигуры островка
- Иконка в трее: автозапуск, показ метрик, выход

## Сборка и запуск

Нужен .NET SDK 10.

```bash
dotnet run --project src/DynamicIsland.App -c Release
```

Самопроверка с метриками (пишет `dynamicisland.log` рядом с exe):

```bash
dotnet run --project src/DynamicIsland.App -- --selftest 8
```

Отрисовать все состояния островка в PNG — тем же кодом, что рисует на экране.
Каждый файл содержит три полосы: тёмный фон, светлый и шахматка, чтобы видеть
края и тень:

```bash
dotnet run --project src/DynamicIsland.App -- --snapshot ./snapshots
```

### Почему нигде нет опроса в цикле

Единственный периодический таймер в приложении просыпается на границе минуты,
чтобы перерисовать часы. Всё остальное приходит событиями: смена трека и
громкости — из WinRT, смена активного окна — из `SetWinEventHook`, заряд — из
`PowerManager`. Любой из этих источников будит цикл отрисовки сообщением
`WM_APP_WAKE`; между событиями поток спит.

### Как устроен кадр

Состоянием back buffer'а управляет только этот код, Skia всегда застаёт ресурс
в объявленном ей состоянии `RenderTarget`:

```
ожидание fence кадра ──► барьер Present → RenderTarget
                    ──► Skia рисует
                    ──► Flush + Submit
                    ──► барьер RenderTarget → Present
                    ──► Present(1)
```

Поэтому обёртки `SKSurface` можно кэшировать на каждый буфер, а не пересоздавать
каждый кадр.

> **Состояние проверки.** Схема корректна по построению, но слоем валидации D3D12
> она пока **не подтверждена**: `D3D12GetDebugInterface` возвращает
> `DXGI_ERROR_SDK_COMPONENT_MISSING` (0x887A002D) — не установлен компонент
> Windows «Средства графики». Установить (нужны права администратора):
>
> ```
> DISM /Online /Add-Capability /CapabilityName:Tools.Graphics.DirectX~~~~0.0.1.0
> ```
>
> После этого отладочная сборка начнёт писать в лог сообщения слоя валидации.
> Пока вместо этого проверяется `GetDeviceRemovedReason` — она ловит только
> грубые ошибки.
