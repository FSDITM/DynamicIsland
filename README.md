# DynamicIsland

Динамический островок для Windows. Переработанная версия
[DynamicWin](https://github.com/FlorianButz/DynamicWin) Флориана Бутца
с новым ядром отрисовки.

## Почему не форк «как есть»

Исходники DynamicWin удалены из репозитория 19 октября 2025 года (коммит
`Remove initial version`, −10 245 строк); там теперь только релизы. Код
восстановлен из истории git и лежит рядом в `../upstream-src` как справочник.

Главная проблема оригинала была не в мелочах, а в архитектуре ядра:

| Что было | Что стало |
|---|---|
| Полноэкранное прозрачное WPF-окно (`AllowsTransparency`) — layered window, весь экран через CPU каждый кадр | Окно-«сцена» размером с островок, `WS_EX_NOREDIRECTIONBITMAP` + DirectComposition, кадр не покидает GPU |
| Софтверный Skia (`SKSurface.Create` поверх `WriteableBitmap`) | Skia на Direct3D 12 через `SkiaSharp.Direct3D.Vortice` |
| 60 fps всегда, даже в покое | Кадр только когда есть что менять; в покое поток спит на нуле CPU |
| WMI-запрос яркости каждый кадр в UI-потоке | Системные метрики — фоновым опросом с кэшем |
| `Vec2` — class, `new List<>` в `Update`/`Draw` каждого объекта каждый кадр | `Vec2` — readonly struct, отрисовка без аллокаций |
| `new SKPaint` / `SKImageFilter` каждый кадр без `Dispose` | Кисти и фильтры кэшируются |

## Замеры

`--selftest` гоняет анимацию и пишет метрики в `dynamicisland.log`.
На AMD Radeon (Ryzen 5 6600H), сцена 1000×300 @ DPI 144:

```
анимация:  59.9 fps, CPU 15.3% одного ядра, 2.56 ms CPU на кадр
первый кадр 78 ms (компиляция шейдеров, разово)
простой:   0.000% одного ядра — поток спит, кадры не рисуются
память:    139 МБ рабочий набор; 245 МБ после первого открытия настроек
```

Замер анимации — намеренно худший случай: `--selftest` раскрывает и сворачивает
островок каждые 0.7 с восемь секунд подряд. В обычной работе островок
неподвижен, и расход нулевой.

Стоимость кадра выросла с 1.18 до 2.56 мс, когда в раскрытый вид добавились
полоса перемотки (с замером ширины текста) и живой эквалайзер. Проверено, что
дело именно в количестве команд отрисовки, а не в размере поверхности:
уменьшение сцены с 945×345 до 855×300 расход не изменило.

Стоимость кадра считается как отрисовка + flush + present. Ожидание fence —
это сон в ожидании GPU, а не работа процессора, и в стоимость не входит.

## Возможности

- Часы и заряд батареи в компактном виде; когда играет музыка — живой эквалайзер
  (~18 кадров в секунду, только пока музыка действительно играет)
- При наведении раскрывается в плеер: обложка, название, исполнитель,
  пауза, переключение треков и **полоса перемотки** — тянется мышью,
  время с обеих сторон; через штатный Windows-API
  `GlobalSystemMediaTransportControls` (работает со Spotify, браузерами,
  любыми плеерами без плагинов)
- **Показ нового трека:** при смене песни островок сам раскрывается на
  несколько секунд и сворачивается обратно
- Кнопки плеера подсвечиваются под курсором
- Все иконки — вектор, без зависимости от глифов шрифта
- **Умная адаптация формы:** сворачивается в тонкую полоску только под теми
  приложениями, которым реально мешает — по умолчанию под браузерами, у них
  сверху вкладки и адресная строка. Терминалу или блокноту эта полоса экрана
  не нужна, и там островок остаётся целым. Список настраивается, приложение
  можно выбрать из запущенных. В полноэкранном режиме (игра, видео) убирается
  совсем
- Раскрыть свёрнутый островок: увести курсор в самую кромку верха экрана и
  задержать на ~0.4 с. Поверх чужого окна это должно быть намеренным жестом —
  иначе островок распахивался бы от случайного движения мыши и накрывал собой
  то, с чем работает человек
- **Оверлей не перехватывает клики.** Окно постоянно держит `WS_EX_TRANSPARENT`
  и физически не может получить ввод; стиль снимается только когда пользователь
  сам навёлся и островок раскрылся. Наведение отслеживается опросом позиции
  курсора — от 3 до 20 раз в секунду в зависимости от того, насколько курсор
  близко
- Иконка в трее: настройки, автозапуск, показ метрик, выход
- **Окно настроек** (WPF, тёмное): размеры всех трёх состояний, скругление,
  цвета, прозрачность, тень, задержки раскрытия, реакция на чужие окна,
  выбор монитора и края экрана, смещение, состав компактного вида,
  глобальная горячая клавиша. Всё применяется сразу, без кнопки «Применить»
- Настройки хранятся в `%APPDATA%\DynamicIsland\settings.json`

## Сборка и запуск

Нужен .NET SDK 10.

```bash
dotnet run --project src/DynamicIsland.App -c Release
```

Самопроверка с метриками (пишет `dynamicisland.log` рядом с exe):

```bash
dotnet run --project src/DynamicIsland.App -- --selftest 8
```

Отрисовать все состояния островка в PNG — тем же кодом, что рисует на экране.
Каждый файл содержит три полосы: тёмный фон, светлый и шахматка, чтобы видеть
края и тень:

```bash
dotnet run --project src/DynamicIsland.App -- --snapshot ./snapshots
```

### Что опрашивается, а что приходит событиями

Событиями приходит всё, что может: смена трека и позиция воспроизведения — из
WinRT, смена активного окна — из `SetWinEventHook`, заряд — из `PowerManager`.
Часы перерисовываются по таймеру на границе минуты. Любой источник будит цикл
сообщением `WM_APP_WAKE`.

Опрашивается ровно одно — позиция курсора. Иначе никак: окно держит
`WS_EX_TRANSPARENT` и сообщений о мыши не получает вовсе. Это осознанный размен:
надёжность важнее красивой цифры. Опрос стоит одного `GetCursorPos` за итерацию
и при курсоре вдали от островка падает до трёх раз в секунду — на замерах
простоя это не видно (0.000% ядра за 25 секунд).

### Как устроен кадр

Состоянием back buffer'а управляет только этот код, Skia всегда застаёт ресурс
в объявленном ей состоянии `RenderTarget`:

```
ожидание fence кадра ──► барьер Present → RenderTarget
                    ──► Skia рисует
                    ──► Flush + Submit
                    ──► барьер RenderTarget → Present
                    ──► Present(1)
```

Поэтому обёртки `SKSurface` можно кэшировать на каждый буфер, а не пересоздавать
каждый кадр.

> **Состояние проверки.** Схема корректна по построению, но слоем валидации D3D12
> она пока **не подтверждена**: `D3D12GetDebugInterface` возвращает
> `DXGI_ERROR_SDK_COMPONENT_MISSING` (0x887A002D) — не установлен компонент
> Windows «Средства графики». Установить (нужны права администратора):
>
> ```
> DISM /Online /Add-Capability /CapabilityName:Tools.Graphics.DirectX~~~~0.0.1.0
> ```
>
> После этого отладочная сборка начнёт писать в лог сообщения слоя валидации.
> Пока вместо этого проверяется `GetDeviceRemovedReason` — она ловит только
> грубые ошибки.

## Шрифт

Островок набран **Inter** (SIL Open Font License), файлы лежат в
`Resources/Fonts` и в систему не устанавливаются.

На маках Dynamic Island набран SF Pro, но вшить его сюда нельзя: лицензия
Apple разрешает использовать SF Pro только при разработке под платформы Apple.
Inter — общепринятая открытая замена с той же геометрией; оригинальный
DynamicWin использовал именно её.

Если SF Pro установлен у вас в системе, укажите его в настройках
(«Содержимое → Шрифт») — приложение возьмёт системный. Использовать
установленный у себя шрифт никто не запрещает, ограничение касается
распространения.
